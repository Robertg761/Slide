# Slide deep bug audit — 2026-08-10

Audited at commit `9c499c4` ("Fix neural swipe ranking and asynchronous whole-word undo").
Method: five subsystem auditors (full-file reads) followed by five independent adversarial
verifiers, all findings below are **verified against the code** — each was confirmed by a
second agent that attempted to refute it. 35 raw findings → 34 confirmed, 1 refuted.

Severities reflect the verifiers' corrections, not the original reports.

---

## Top-priority bugs

### 1. Typing during a swipe decode corrupts the whole input pipeline
**`ime/.../SlideInputMethodService.kt:1012` (`processOrderedFollowup`) — HIGH**

`processOrderedFollowup` registers ONE net selection expectation for `action()` and does
not wrap the action in `beginBatchEdit`/`endBatchEdit`. Multi-step actions reachable
through the ordered queue issue several InputConnection mutations, each producing its own
`updateSelection` callback:
- `handleCharacter` auto-space: `commitText(" ")` at :1897 then `setComposingText` at :1919/:1924
- `handleSpace` double-space-period: `deleteSurroundingText(1,0)` + `commitText(". ")` at :1987-1988

The intermediate callback matches nothing in `ExpectedSelectionTracker` (it only matches
on the final `to`), `selfEdit` was already cleared synchronously at :1028, so the callback
is classified `externalSelectionChanged`. That branch (:2846-2866) then:
- cancels the ordered input queue → **already-accepted keystrokes silently dropped** (see #3)
- `expectedSelections.invalidate()` → the *final* callback is misclassified too
- `gestureUndoState.invalidate()` → the just-armed whole-word swipe undo is destroyed
- `abandonComposing()` + `clearSuggestions()` → composing word and gesture alternatives wiped
- `reopenWordAtCursor(stale offset)` → composing region set on the wrong characters (see #2)

Scope (verified): only reachable while a swipe decode is in flight — a "typing during
swipe decode" bug, not every-keystroke — but deterministic within that window. Note every
other multi-op path (`pickGestureAlternative` :1429, `deleteLastGestureCommit` :2081,
`revertAutocorrect` :2663, `pickTypedSuggestion` :2721, `commitPrediction` :2785) already
uses batch edits; this one was missed.
**Fix direction:** wrap `action()` in begin/endBatchEdit, or register per-step expectations.

### 2. `reopenWordAtCursor` mixes callback offset with live editor text
**`SlideInputMethodService.kt:2910` — HIGH (consequence of #1)**

`regionStart = selectionStart - (before.length - start)` uses the callback-supplied cursor
while `before`/`after` are read from the live InputConnection (:2893-2894). With a stale
callback (produced by #1, or any editor that delays callbacks past a subsequent IME
mutation), `setComposingRegion` lands shifted; a later `setComposingText`
(`finishComposing` :2591, `pickTypedSuggestion` :2722) replaces the wrong characters —
visible text corruption. Fixing #1 removes most reachability; the mismatch stays latent.

### 3. Selection-change handler cancels the ordered input queue, dropping keystrokes
**`SlideInputMethodService.kt:2846` — MEDIUM**

`externalSelectionChanged` → `cancelGestureInputSequence()` → `OrderedInputQueue.cancel()`
cancels every queued job, including `processKeyCommit` actions for keys already pressed.
No replay exists; the characters never reach the editor. This violates the queue's own
KDoc ("Cancellation is reserved for editor/session transitions"). Triggers on genuine
external cursor moves (app-side TextWatcher reformat during a pending swipe) as well as
the self-inflicted misclassification from #1.

### 4. Transient settings read failure can permanently wipe learned data
**`core/.../KeyboardSettings.kt:145` — MEDIUM (narrow trigger, permanent loss)**

The settings flow's `catch` emits whole-defaults `KeyboardSettings(incognitoModeEnabled=true)`
carrying `learnedDataClearEpoch = 0`. The service compares epochs with `!=` (:335-348), so
a drop from N→0 is treated as a user clear request: `clearLearnedDataFromMemoryAndDisk()`
empties `userDictionary`/`userBigrams`/`spatialTouchModel` in memory; the next learning
event (or `flushFinalLearnedData`, which persists "even an empty snapshot") overwrites the
on-disk files. Verified against DataStore 1.2.1 bytecode: a post-init read failure does
reach an already-collecting consumer (`ReadException` through the shared cache), and a
failed `edit()` bumps the version pre-write, arming a disk re-read. Requires a successful
first emission (first-emission failure takes the initial-load branch instead).
Same line, two more defects: the `catch` **completes the flow**, so the keyboard stops
receiving all settings changes until service recreation, and the fallback silently reverts
every live setting (theme, haptics, offensive-word filter, incognito forced on).
**Fix direction:** re-emit the last-known settings (or only epoch-preserving defaults) and
resubscribe; compare epochs with `>` or track per-device monotonically.

### 5. Corrupt prefs file crash-loops the keyboard via the recentEmoji flow
**`core/.../KeyboardSettings.kt:196` — MEDIUM-HIGH**

`migrateLegacyRecentEmoji()` calls `context.dataStore.data.first()` outside any catch —
it runs in the `recentEmoji` flow builder *before* the inner `.catch` (which guards only
`recentEmojiStore.data`) and in `recordEmojiUse`. Consumers (`onCreate` `launchIn` :399,
`scope.launch { update/recordEmojiUse }` at :1311/:1846/:1851) have no try/catch and the
scope has no `CoroutineExceptionHandler` → uncaught → IME process death. A persistently
corrupt `slide_settings.preferences_pb` (no `ReplaceFileCorruptionHandler` configured)
crashes the keyboard **on every start**, while the hardened `settings` flow beside it
survives. Disk-full `edit()` from the emoji panel is the transient variant.

## Input pipeline (SlideInputMethodService + text/)

6. **:2821 — cachedSelection regresses to intermediate position mid-chain (LOW-MEDIUM).**
   `cachedSelectionStart/End` overwritten before `expectedSelections.consume()` retires
   only a prefix of a multi-entry chain (gesture finish+commit registers A→B, B→C). Self-
   heals on the next callback, but a Backspace landing between the two callbacks hits
   `GestureUndoState.consume`, which sets `pending = null` *before* the cursor equality
   test — the whole-word undo is permanently downgraded to a one-char delete.
   `processCursorMove` `setSelection` from the stale base is also reachable.

7. **:2148 — `readEditorSelection` extracts the entire document, ~4-6× per swipe (MEDIUM).**
   Default `ExtractedTextRequest` (hint fields 0) makes AOSP editors marshal the full text
   over a blocking Binder call on the IME main thread — just to read two ints. The repo's
   own comment at :620-622 avoids `getExtractedText` for exactly this reason. Large
   documents → per-swipe stalls; Binder-limit failure → null → `processOrderedFollowup`
   registers no expectation → misclassification cascade.

8. **:2186/:1981 — double-tap windows measured at execution time, not press time (LOW).**
   Queued shift/space taps behind a swipe decode compress the measured interval; a slow
   double shift-tap can register as caps lock. Realistic case: tap 1 queued, tap 2 after
   the queue drains. The casing path (:852-856) got execute-time treatment deliberately;
   the timers did not.

9. **`text/PrecedingWord.kt:80` — bare apostrophe returned as preceding word (LOW).**
   `beforeNewWord("he said '")` → `"'"`. Flows into the decoder as `previousWord` and into
   `learnPair` (which filters only null/empty, unlike `learnWord`) → bogus user bigram
   keyed on `'`. No trailing-apostrophe test exists.

10. **`text/TextCase.kt:8` — capitalize branch tests first CHAR, not first letter (LOW).**
    `matchTypedCase("'Hello", "hello")` drops the capital on autocorrect (apostrophe is a
    composing word char). Inconsistent with the all-caps branch, which filters to letters.

11. **:1854 — `onEmojiBackspace` edits without selfEdit/expectation/queueing (LOW).**
    Resulting callback always classified external. Impact currently contained
    (`reopenWordAtCursor` bails while `emojiPanelShown`), but the classification is wrong
    and the same callback still runs `cancelGestureInputSequence()`.

## View layer (multi-touch is the systemic theme)

12. **`KeyboardView.kt:1020` — any finger's lift consumes the alternates popup (MEDIUM).**
    `handlePointerUp` checks `alternatesPopup.isShowing` without an ownership check
    (the MOVE path at :977 does check `pointer.longPressFired`). Second finger tap-release
    while an accent popup is open → popup selection committed, attributed to the wrong
    `Key` (poisoning corrector input; touchX/Y NaN); the owning finger's lift commits
    nothing. Bonus defect: the second pointer's rescheduled long-press can re-show the
    popup over its own key while finger 1 still owns it.

13. **`KeyboardView.kt:810` — emoji-search header ignores POINTER_DOWN/UP (MEDIUM).**
    Second finger in the header resolves to the nearest top-row key (`KeyGeometry.hitTest`
    never returns null; keys sit below the header offset) and types into the query; a
    header finger lifting as POINTER_UP is swallowed, so `pressedSearchResult` survives
    and an unrelated finger's UP inserts that emoji.

14. **`VoiceOverlayView.kt:357` — POINTER_DOWN falls through to the release path (MEDIUM).**
    `when` early-returns only for DOWN/MOVE/CANCEL. A second finger touching the overlay
    *ends the dictation* — commit or cancel depending on where finger 1 started.

15. **`SuggestionStripView.kt:195` — long-press survives a suggestion-list swap (MEDIUM).**
    `setSuggestions` doesn't cancel the posted long-press runnable, which captured only an
    int index and re-resolves `words[index]` at fire time. An async strip update during
    the ~500 ms hold → `onSuggestionHeld` permanently learns/forgets the *wrong* word in
    the user dictionary.

16. **`EmojiPanelView.kt:774` — tone popup survives ACTION_CANCEL (MEDIUM).**
    `cancelTouch()` clears press state but not `popupIndex`/`popupPosition` (`reset()`
    clears exactly those — the omission is visible). With stale `popupIndex >= 0`, any
    later tap (footer 'ABC', a tab, another emoji) inserts the popup's emoji; if x falls
    inside the stale popup rect it also silently changes the default skin tone.
    Practical trigger: parent intercept / window losing the touch stream.

17. **`KeyboardView.kt:998` — single global long-press slot (LOW).** Any other pointer's
    lift (or press on an alternate-bearing key — i.e. every letter) cancels a pending
    long-press. Two-thumb typists rarely see accent popups.

18. **`KeyboardView.kt:986` — slide-off cancels another pointer's backspace repeat (LOW).**
    No-arg `cancelRepeat()` where the pointer-scoped overload is used everywhere else;
    repeat never re-arms while the finger stays down.

19. **`KeyboardView.kt:895` — no `gesturePointerId` guard in `handlePointerDown` (LOW).**
    A palm/second-finger contact mid-swipe fires onKeyDown (click+haptic), clears the
    previous gesture trail, and commits a stray letter on lift.

20. **`KeyboardView.kt:1000` — shared key-preview popup, rollover lift kills it (LOW).**
    Root cause: single shared preview window, not per-pointer.

21. **`EmojiPanelView.kt:757` — grid reads pointer index 0 only (LOW).** First finger
    lifting as POINTER_UP is ignored → scroll jumps by the inter-finger distance; a
    motionless second finger's UP commits the first finger's emoji.

## Engine

22. **`SpatialTouchModel.kt:75` — transposition corrections poison the touch model (MEDIUM).**
    `observe()` aligns typed↔corrected with plain Levenshtein (no transposition op) while
    the corrector offers transpositions at cost 0.45 — so accepting "gerat"→"great" from
    the strip attributes each touch to the *other* key. Adjacent keys (distance 1.0) pass
    the 1.35 gate; `add()` has no mean clamp; on a fresh slot one observation sets
    meanX a full key width off. Result: e↔r substitutions become ~free both ways AND a
    genuine adjacent-key slip now measures 2.0 > neighbourRadius 1.2 and is dropped.
    Scope: only the strip-tap path learns touches from corrections
    (`pickTypedSuggestion` → `learnTouches(typed, replacement)`); space-bar autocorrect
    doesn't. **Fix direction:** use Damerau alignment, or skip learning on transposed pairs.

23. **`TypingSuggester.kt:470` — proper-noun penalty applied after TopK truncation (LOW).**
    Completions enter the 4-slot board unpenalised; corrections are penalised before their
    board. Verified against the real lexicon: prefix "geo" fills the strip with
    Geos/Georg/Geoff/George while "geode"/"geology" are never offered; same for
    "sam"→"sample", "pau"→"pauses".

24. **`GestureDecoder.kt:287` — `-Infinity` candidates surface on the classic path (LOW).**
    Degenerate templates (<2 corners) return NEG_INFINITY; `ScoreBoard.offer` inserts it
    while the board isn't full. The classic decoder is the *published* decoder until the
    neural model loads (and forever if load fails); only the neural wrapper filters
    non-finite scores. 16 degenerate words exist in the shipped lexicon ("mm", "tt", …).
    Commit requires it to be the only survivor (tight loop on one key); it appears in the
    preview strip more readily.

25. **`SpatialTouchModel.kt:157` — `add()` unclamped, `restore()` clamps to ±0.65 (LOW).**
    The IME persists via a `restore()`-based snapshot, so a live mean beyond 0.65 silently
    changes after the next process restart — same learned data, different behaviour.

REFUTED: TypingSuggester.kt:275 row-buffer sizing (short by apostrophe count) — the
sizing relation is genuinely wrong (`+3` is only correct for apostrophe-free words) but
unreachable: max lexicon word is 28 chars, longest apostrophe word 21. Latent only.

## Lexicon/asset loaders (shared pattern)

26. **`LexiconLoader.kt:70`, `BigramLoader.kt:77`, `TrigramLoader.kt:43`,
    `EmojiData.kt:104` — corrupt-but-right-length assets crash-loop the IME (LOW, hardening).**
    Decode loops index header-declared sizes with no bounds checks; `load()` catches
    IOException only, so AIOOBE escapes into unguarded `scope.launch` in `onCreate`
    (no `CoroutineExceptionHandler` anywhere) → process death on every keyboard open,
    instead of the documented degrade-gracefully path. `EmojiData` additionally
    sign-extends the category byte (`.toByte()` stored, `.toInt()` read → ids >127 go
    negative). BigramLoader's non-monotonic-but-in-range offsets don't crash at load but
    silently corrupt `Bigrams.score` ranges. Input is the packaged APK asset only, hence
    hardening rather than live bug — but one `catch (e: Throwable)` per loader (or a
    CoroutineExceptionHandler on the scope) converts a crash loop into a degraded feature.

27. **`UserDictionaryStore.kt:244` — no parent-directory fsync after rename/marker create
    (LOW).** File contents are synced; the directory entry isn't. Power-cut window in
    which a user's explicit "clear learned data" can be resurrected on reboot.
    (Android's own AtomicFile shares the omission.)

## App / update flow

28. **`MainActivity.kt:117` + `UpdateManager.kt:97/:137` — rotation during download →
    concurrent downloads over a shared `.part` path (MEDIUM as a cluster).**
    Three confirmed defects compose: `downloading`/`availableUpdate` are plain `remember`
    (reset on recreation; the LaunchedEffect re-checks and re-shows the dialog);
    `downloadAndInstall` is straight-line blocking code under `withContext(IO)` with no
    suspension points (cancellation is never observed — the installer prompt fires
    minutes after the user left; `runCatching` also swallows CancellationException);
    and `download()` has no mutex, wipes the shared directory, hashes the network stream
    but zip-checks/renames *by path*. Verified NOT a security hole (same HTTPS URL, and
    `verify()` re-reads the renamed file, Android re-verifies signatures at install) —
    the outcome is confusing failures ("Android could not read the downloaded APK") and
    wasted bandwidth. **Fix direction:** hoist state into a ViewModel, add suspension
    points/`ensureActive()` to the loop, single-flight the download.

29. **`UpdateManager.kt:134` — APK staged in `cacheDir`, never pinned (LOW).**
    `getAllocatableBytes` is only *queried* — it reports space the platform is willing to
    reclaim *by clearing caches*, including this one. On low-storage devices the staged
    APK can be evicted between `startActivity` and the user confirming install.
    Move to `filesDir` + `<files-path>`, or call `allocateBytes()`.

30. **`VoiceInputClient.kt:138` — `bindService == false` leaves the ServiceConnection
    registered (LOW).** `clearBindingRegistration()` exists for the onNullBinding path but
    isn't called here, and `unbind()` early-returns when `!bound`, so teardown never
    cleans it. Bounded to one dangling entry (dispatchers keyed by connection), narrow
    trigger. "ServiceConnection leaked" warning on IME destroy.

31. **`AudioRecorder.kt:214` — final ~100 ms audio chunk discarded on stop (LOW,
    deliberate tradeoff).** The double drop (`stopRequested` check post-read + in
    `append`) exists so no audio can land after the privacy wipe (commit eff4cf2) — but
    it clips the tail of the last word on the normal path too. A fix must gate appends on
    "not yet drained" under `samplesLock` rather than on `stopRequested`, preserving the
    wipe invariant on the timeout path.

## Cross-cutting themes

- **Multi-touch is systematically unhandled in the view layer** (findings 12-21): missing
  `ACTION_POINTER_DOWN/UP` cases, single-slot state (long-press, preview, popup) with no
  pointer ownership. One sweep adding per-pointer bookkeeping would fix most of them.
- **No `CoroutineExceptionHandler` on the IME scope** turns every non-IOException in a
  loader or DataStore flow into keyboard process death (findings 5, 26).
- **The async selection-expectation machinery** (`ExpectedSelectionTracker`) is well
  designed for per-step chains but two call sites feed it net-change expectations or
  bypass it (findings 1, 6, 11); the external-classification fallout is destructive
  (findings 2, 3).
- **Hardened-vs-unhardened siblings**: `settings` flow has a catch, `recentEmoji` doesn't;
  `restore()` clamps, `add()` doesn't; MOVE path checks popup ownership, UP path doesn't.
